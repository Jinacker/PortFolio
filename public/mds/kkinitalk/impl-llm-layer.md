# LLM 연동 계층 — 비결정적 출력을 계약으로 묶기

> 추천 문구·복약 주의사항·식사 코멘트가 LLM 출력인데, 이 응답은 **DB에 저장되고 앱 화면에
> 그대로 그려집니다.** 형태가 한 번만 틀려도 화면이 깨지고, 건강 문구라
> "고혈압이시네요" 같은 진단성 표현이 나가면 안 됩니다.

## 문제

- provider마다 JSON 강제 방식이 다름 — OpenAI는 `response_format`, Gemini는 `responseMimeType`,
  Anthropic은 특정 파라미터를 아예 안 받음(전달하면 400)
- 키가 없으면 서버가 안 뜨는 구조면 개발·CI·대시보드가 전부 막힘
- 재시도가 여러 곳에 생기면 실패 1건이 호출 4건이 되어 **비용이 폭주**
- 의료 고지 문구를 LLM이 매번 다르게 씀

## 선택

**재시도·파싱은 베이스 클래스에 한 번만** — provider 4종(mock/openai/gemini/anthropic)은
"텍스트 1회 호출"만 구현합니다. `코드펜스 제거 → json.loads → 1회 재시도 → 재실패 502`가
한 곳에만 존재하므로, **"재시도는 1회" 정책이 provider마다 달라질 수 없는 구조**가 됩니다.
문서에 적는 것과 구조로 강제하는 것은 결과가 다릅니다.

**키 미설정은 기동 실패가 아니라 호출 시점 503** — 서버 기동은 항상 성공해야 개발·CI가 돕니다.

> 다만 이 "관대한 기본값" 원칙을 챗봇에 그대로 가져갔다가 **운영에서 가짜 응답이 사용자에게
> 나가는 사고**를 겪었습니다(트러블슈팅 · 가짜 AI 문서). 개발 편의를 위한 기본값이
> 운영까지 따라가면 안 된다는 것을 그때 배웠습니다.

**의료 고지는 LLM에게 맡기지 않음** — `disclaimer`는 상수를 코드에서 주입하고 LLM 출력은
무시합니다. **법적 고지 문구가 모델의 표현 변화에 좌우되면 안 되기 때문**입니다.

**mock은 입력 반영형** — 고정 응답이면 "입력이 문구에 반영되는가"를 테스트할 수 없습니다.
mock이 입력의 부족 영양소·약 이름을 응답에 반영하게 해, **키 없이도
"단백질이 부족하면 문구에 단백질이 나오는가"까지 검증**됩니다.

## 결과

- provider 4종이 `generate_json(system, user) → dict` 하나로 통일
- 재시도 상한은 **일부러 깨진 출력을 내는 `GarbageLLM`을 주입해 `calls == 2`를 단언** —
  내부 호출 횟수는 블랙박스로 관측 불가한 것이라 화이트박스로 고정
- 프롬프트를 `기본 원칙 → 판단 우선순위 → 출력 규칙 → Few-shot → 출력 형식` 골격으로 구조화 —
  판단 우선순위(안전·정확성 > 지병 > 기피음식 > 부족 영양소)를 명시
- 토큰·비용은 `contextvars`로 **요청 단위 격리 집계** — 공유 인스턴스에 저장하면 동시 요청끼리 값이 섞임

## 배운 점

- 비결정적 출력은 **결정적인 층으로 감싸야 한다** — 파싱·재시도·검증·상수 주입이 전부 그 층이다
- 정책은 **구조로 강제해야 지켜진다** — 문서의 "재시도 1회"와 베이스 클래스의 1회는 다르다
- 안전에 관한 것은 **LLM에게 맡기지 않는다** — 고지 문구는 상수여야 한다
