# GPT Vision 건당 비용 12배 절감

> 측정하지 않으면 보이지 않는 비용을, 실측으로 찾아 줄인 기록

## 문제 상황

어르신이 식사할 때마다 사진을 올린다. **1일 3~4끼 × 사용자 수**만큼 Vision이 호출된다.
그런데 **아무도 건당 비용을 몰랐다.** OpenAI 대시보드의 월 합계만 있었고,
그게 분석 때문인지 문구 생성 때문인지도 구분되지 않았다.

이 값을 모르면 요금제도, 무료 사용량 한도도, **자체 모델 전환 시점**도 정할 수 없다.

## 원인 분석 — 재현 가능한 측정부터

추정하지 않고 측정했다. 위키미디어 돌솥비빔밥 사진을 **서버와 완전히 동일한 경로**
(다운로드 → EXIF 처리 → 1280px 리사이즈 → JPEG base64)로 처리한 뒤
`/chat/completions`를 실제 호출해 응답의 `usage`를 읽었다.

- 입력 **37,009 토큰** / 출력 33 토큰 → **건당 8.08원**
- 비용의 **거의 전부가 이미지 입력 토큰**. 출력은 JSON 몇십 토큰뿐

`gpt-4o-mini`는 이미지 토큰 배율이 커서 **1280px 사진 한 장이 3.7만 토큰**이 된다.

## 선택지 비교

### 해상도를 낮춘다 vs 비전 상세도를 낮춘다

| 후보 | 효과 | 문제 |
|---|---|---|
| `IMAGE_MAX_DIMENSION`을 768로 축소 | 업로드 대역·처리시간 감소 | **토큰은 거의 안 줄어든다.** 타일 계산 방식이라 해상도에 비례하지 않음 |
| **`detail: low` 적용** | 저해상 고정치로 취급 → 타일 수와 무관하게 토큰 고정 | 정밀 인식이 필요하면 품질 저하 가능 |

**선택 기준은 "우리가 이미지에서 뽑는 정보가 무엇인가"** 였다.
이 파이프라인이 GPT에게 요구하는 것은 **음식 이름과 면적 비중**이다.
글자를 읽거나 미세한 질감을 판별하지 않는다.
**저해상도로 충분한 작업에 고해상도 요금을 내고 있었다.**

리사이즈 상한(1280px) 하드코딩도 설정값으로 뺐다. `detail:low`에서는 토큰이 해상도와 무관해
**비용 관점의 주 레버는 아니지만**, 로컬(SAM) 백엔드 품질에는 영향을 주므로 조정 가능해야 했다.

## 결과 — 측정으로 검증

| 설정 | 입력 토큰 | 출력 토큰 | 건당 비용 |
|---|---|---|---|
| `detail` 기본(고해상, 1280px) | 37,009 | 33 | 약 **8.08원** |
| **`detail: low`** | 3,007 | 33 | 약 **0.68원** |

- **건당 8.08원 → 0.68원, 약 12배 절감**
- 인식 품질 유지 확인 — 동일 사진 `bibimbap` **confidence 0.9**
- `pytest 68 passed`(당시) — 리사이즈 상한 설정화 후에도 SSRF·리사이즈 테스트 전부 통과

**이 수치가 있으니 자체 모델 전환 손익분기를 계산할 수 있었다.**

| 방식 | 비용 |
|---|---|
| GPT API | 건당 0.68원, 운영 부담 0 |
| GPU 인스턴스(T4 24/7) | 월 15만~38만원 + 운영 부담 |

손익분기 **월 약 44만 건**. 절감 전 8원 기준이었다면 월 3.7만 건에서 역전됐을 것이다.
즉 **이 최적화 하나가 "자체 모델을 올려야 한다"는 판단을 한참 뒤로 미뤘다.**

그리고 이후 **응답에 `usage`(토큰·예상 비용)를 실어** 대시보드에서 호출마다 볼 수 있게 했다.
`contextvars`로 요청 단위 격리 — 공유 인스턴스에 저장하면 동시 요청끼리 값이 섞인다.

## 남은 한계

- 측정 표본이 **사진 1장**이다. 반찬 수가 많은 상차림은 토큰이 다를 수 있다
- `detail:low`가 인식 품질에 주는 영향을 **1건으로만** 확인했다. **정확도 회귀 세트가 없다**
- 정밀 인식이 필요해지면 `high`로 올려야 하고 비용이 다시 12배가 된다.
  그 판단 기준이 문서에만 있고 코드로 자동화돼 있지 않다

## 배운 점

- 비용은 **기능이 아니라 설정에 숨어 있을 수 있다는 것.** 로직을 한 줄도 안 고치고 12배가 줄었다
- 최적화 전에 **동일 경로로 재현하는 측정 스크립트**부터 만들어야 한다는 것
- "싼 것을 골랐다"가 아니라 **"이 작업에 그 품질이 필요한지"를 먼저 물어야 한다는 것**
