# 부하·동시성 — 코드에만 있던 안전장치를 처음으로 증명

> 추론 서버가 죽는 네 가지 방식을 막아 뒀는데, 막히는지는 확인한 적이 없었다

## 문제 — "코드에 있다"까지였다

구현 2에서 추론 서버 특유의 고장 방식 네 가지를 다뤘다. 그런데 **전부 미검증**이었다.

| 장치 | 코드 | 그때까지의 검증 |
|---|---|---|
| 세마포어로 동시 추론 제한 | `async with state.inference_semaphore` | 없음 |
| 전체 타임아웃 → 504 | `asyncio.wait_for(..., 60s)` | 없음 |
| 동기 추론을 executor 로 오프로드 | `run_in_executor` | 없음 |
| 다운로드 타임아웃 → 502 | `httpx.Timeout(10s)` | 단위 테스트만 |

세 번째가 특히 뼈아팠다. 문서에 이렇게 써 놓고 한 번도 확인하지 않았다.

> *"추론 1건이 도는 동안 `/health`조차 응답하지 못하면 로드밸런서가 인스턴스를 죽인다.
> **추론이 느린 것이 서버가 죽은 것으로 오판되는** 최악의 시나리오다."*

## 왜 실 GPT가 아니라 mock 인가

| 후보 | 문제 |
|---|---|
| 실 GPT로 동시 요청을 건다 | 응답이 **2~13초로 흔들려** "세마포어 때문에 밀린 건지 API가 느린 건지" 구분되지 않는다. rate limit도 걸린다 |
| **mock에 고정 지연을 주입** | 큐잉이 **산술로 드러난다** — 지연 1초 · 6건 · 동시성 1이면 6초, 3이면 2초여야 한다 |

**결정론이 목적이지 비용 절약이 아니다.** 비용 0원은 부수 효과다.

같은 이유로 **타임아웃은 값을 낮춰(60초 → 2초)** 쟀다.
60초를 실제로 기다리는 것은 같은 메커니즘을 30배 느리게 확인하는 것뿐이다.
대신 **운영 기본값이 60초인지는 별도 시나리오로 단언**했다 —
안 그러면 "60초를 쟀다"로 읽힌다.

## 🔴 첫 실행이 전부 422로 죽었다

```
concurrency=1  총 0.06초 (기대 ≈6초)  200 0/6
  단건: 422 FORBIDDEN_IMAGE_HOST
```

**SSRF 방어가 로컬 이미지 서버(127.0.0.1)를 차단**했다.
부하 테스트를 막은 것이지만, 동시에 **방어가 실제로 동작한다는 우연한 증거**였다.

(mock 백엔드도 이미지 다운로드는 실제로 수행한다 — 그게 하네스의 에러 계약 검증을
가능하게 하는 설계다. 그래서 부하 테스트에도 진짜 이미지 호스트가 필요하다.)

### 문을 열되 자물쇠를 둘로 걸었다

| 후보 | 문제 |
|---|---|
| 부하 테스트에서만 SSRF 검사를 통째로 끄는 플래그 | **실수로 운영에 켜지면 SSRF가 활짝 열린다** |
| 외부 공개 이미지(위키미디어)를 쓴다 | 네트워크 왕복이 측정에 섞이고, 남의 서버에 부하를 준다 |
| **`ALLOW_PRIVATE_IMAGE_HOSTS` + 허용목록 동시 요구** | 설정이 둘로 늘어남 |

세 번째. **플래그만 켜면 아무 효과가 없다.**

```python
skip_private_check = settings.allow_private_image_hosts and bool(allowed)
```

`ALLOWED_IMAGE_HOSTS`가 비어 있으면 건너뛰지 않으므로,
**"실수로 하나만 켜서 활짝 열리는" 상태 자체가 없다.**
사내망 오브젝트 스토리지처럼 사설 IP가 정당한 경우에도
**어떤 호스트인지 반드시 명시하게 강제**한다.

이건 **가짜 챗봇 사고(트러블슈팅 7)의 교훈을 새 위험 설정에 바로 적용**한 것이다 —
*위험한 설정의 기본값은 "동작하지만 위험"이 아니라 "동작하지 않음"이어야 한다.*

자물쇠가 하나만으로는 안 열린다는 것을 단위 테스트 4건으로 고정했다.

## 결과 — 측정으로 검증

### A. 세마포어 큐잉

지연 1.0초 고정, 동시 6건.

| 동시성 | 총 소요 | 기대 | 200 |
|---|---|---|---|
| 1 | **6.15초** | ≈6초 | 6/6 |
| 3 | **2.09초** | ≈2초 | 6/6 |

**산술이 그대로 맞는다.** 동시 요청이 실제로 직렬화된다.

### B. 전체 타임아웃

```
단건 (지연 4초 > 타임아웃 2초)  →  504 INFERENCE_TIMEOUT  at 2.01초
```

**세마포어 대기까지 타임아웃에 포함되는가**가 진짜 확인할 것이었다.
동시 3건 · 지연 1.5초 · 타임아웃 2초:

```
상태코드 [200, 504, 504]   최장 2.04초
```

앞 1건만 통과하고 **뒤 2건은 대기 중에 504로 끝난다.**
`wait_for`가 세마포어 획득까지 감싸지 않았다면 뒤 요청들이 무한정 밀렸을 것이다.

### C. 이벤트 루프 — 가장 중요한 결과

`mock`의 지연을 `asyncio.sleep`(비블로킹)과 `time.sleep`(블로킹)으로 **대조**했다.
블로킹 쪽은 버그가 아니라 **대조군**이다 — 동기 추론(torch·SAM)을
`run_in_executor` 없이 async 핸들러에서 부르면 정확히 그렇게 된다.

| | `/health` 폴링 횟수 | p50 | p95 | 최악 |
|---|---|---|---|---|
| 비블로킹 (현재 코드) | **85회** | **3ms** | 5ms | **17ms** |
| 블로킹 (대조군) | **4회** | **1,474ms** | 1,549ms | **1,549ms** |

**폴링 횟수 85 → 4가 그 자체로 증거다.**
같은 시간 동안 헬스체크를 4번밖에 못 찍었다 — **이벤트 루프가 멈춰서 폴링조차 못 했다.**
지연은 1.5초였는데 `/health` 최악이 1,549ms다. **정확히 추론 시간만큼 막힌다.**

로드밸런서 헬스체크 타임아웃이 보통 1~5초인 것을 생각하면,
이 상태에서는 **추론이 도는 동안 인스턴스가 비정상으로 판정되어 제거된다.**

### D. 다운로드 타임아웃

```
느린 호스트(3초) + 타임아웃 1초  →  502 IMAGE_FETCH_FAILED  at 1.04초
```

**502인 것이 중요하다.** 사설 IP 차단(422)과 구분되어야
백엔드가 "재시도할 가치가 있는가"를 판단할 수 있다.

### E. 운영 기본값

메커니즘을 낮은 값으로 쟀으므로 실제 설정을 따로 단언했다.

```
inference_timeout_sec = 60.0     image_fetch_timeout_sec = 10.0
llm_timeout_sec = 30.0           inference_concurrency = 1
전체 타임아웃 > 다운로드 + LLM   →  60.0 > 10.0 + 30.0
```

마지막 줄이 핵심이다. **바깥 타임아웃이 안쪽의 합보다 커야** 하위 타임아웃이 의미를 갖는다.
안쪽이 더 길면 바깥이 항상 먼저 터져 계층이 무의미해진다.

`pytest 105 passed` · 실 API 호출 **0회** · 비용 **0원**.

## 남은 한계

- **GPU 경로(`local` 백엔드)는 여전히 못 쟀다.** 인스턴스가 없어 SAM 추론 시간·VRAM 피크·
  콜드스타트는 문서상 추정치로 남는다. 이 테스트가 증명한 것은 **오케스트레이션 계층**이다
- **실 트래픽 규모의 부하가 아니다.** 동시 6건까지만 봤다.
  수백 동시 요청에서의 커넥션 풀·메모리는 안 봤다
- **처리량(throughput) 곡선이 없다.** 동시성을 올리며 RPS가 어디서 꺾이는지 모른다
- 블로킹 대조군은 **mock에 넣은 것**이다. 실제 `local` 백엔드의 `run_in_executor`가
  GPU 환경에서 의도대로 도는지는 별개 확인이 필요하다

## 배운 점

- **"코드에 있다"와 "동작한다"는 다르다는 것.** 세마포어·타임아웃·오프로드가 전부 있었지만
  어느 것도 밟아 본 적이 없었다
- **대조군이 있어야 증명이 된다는 것.** 비블로킹만 재면 "17ms 나왔다"이지만,
  블로킹과 나란히 놓으면 **"막히는 코드였다면 1,549ms였다"** 가 된다
- **측정하려다 다른 방어를 밟는 것 자체가 검증이라는 것.** 422로 죽은 첫 실행이
  SSRF 방어의 첫 실서버 확인이었다
- 위험한 문을 열 때는 **자물쇠를 둘로** — 하나만 실수로 풀려도 안 열리게
