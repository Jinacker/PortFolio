# 부하·동시성 — 코드에만 있던 안전장치를 처음으로 증명

> 추론 서버가 죽는 네 가지 방식을 막아 뒀는데, 막히는지는 확인한 적이 없었다

## 왜 필요했나

- 세마포어·타임아웃·executor 오프로드가 전부 코드에 있었지만 **한 번도 밟아 본 적이 없었다**
- **"코드에 있다"와 "동작한다"는 다르다**

## 어떤 선택지가 있었고, 무엇을 선택했나

### 실 GPT vs mock 고정 지연

- 실 GPT는 응답이 2~13초로 흔들려 **세마포어 때문인지 API가 느린 건지 구분 불가**
- mock에 고정 지연을 주입하면 큐잉이 **산술로 드러난다** — 지연 1초·6건·동시성 1이면 6초, 3이면 2초
- **결정론이 목적이지 비용 절약이 아니다** — 비용 0원은 부수 효과
- 타임아웃은 값을 낮춰(60초 → 2초) 메커니즘을 재고, **운영 기본값이 60초인지는 별도 시나리오로 단언**

### 첫 실행이 전부 422로 죽었다

- **SSRF 방어가 로컬 이미지 서버(127.0.0.1)를 차단** — 부하 테스트를 막았지만, 방어가 동작한다는 우연한 증거
- 테스트용 예외도 **자물쇠 2중** — 예외 플래그와 허용 호스트 목록을 동시에 요구해, 하나만 실수로 켜져도 열리지 않게

## 결과 — 측정으로 검증

| 검증 | 결과 |
|---|---|
| 세마포어 큐잉 (지연 1s × 6건) | 동시성 1 → **6.15초** / 동시성 3 → **2.09초** — 산술 그대로 |
| 전체 타임아웃 | 동시 3건 → `[200, 504, 504]` — **대기 중인 요청도 명시적 504** |
| 다운로드 타임아웃 | 느린 호스트 → **502** (사설 IP 차단 422와 구분) |
| 운영 기본값 | `60.0 > 10.0 + 30.0` — 바깥 > 안쪽 합을 시나리오로 단언 |

가장 중요한 결과 — **이벤트 루프 대조 실험.** mock 지연을 비블로킹과 블로킹으로 나란히 쟀다.
블로킹 쪽은 동기 추론을 executor 없이 부르면 정확히 그렇게 되는 **대조군**이다.

| | `/health` 폴링 횟수 | p50 | 최악 |
|---|---|---|---|
| 비블로킹 (현재 코드) | **85회** | **3ms** | 17ms |
| 블로킹 (대조군) | **4회** | **1,474ms** | 1,549ms |

- 같은 시간에 헬스체크를 4번밖에 못 찍었다 — **루프가 멈춰 폴링조차 못 했고, 정확히 추론 시간만큼 막혔다**
- 로드밸런서 타임아웃(보통 1~5초) 기준, 이 상태면 **추론이 도는 동안 인스턴스가 제거된다**
- pytest 105 passed · 실 API 호출 0회 · 비용 0원

## 남은 한계

- **GPU 경로는 여전히 못 쟀다** — 증명한 것은 오케스트레이션 계층
- 동시 6건까지만 — 수백 동시 요청의 커넥션 풀·메모리는 안 봤다

## 경험을 통해 배운 점

- **"코드에 있다"와 "동작한다"는 다르다**는 것
- **대조군이 있어야 증명이 된다**는 것 — "17ms 나왔다"가 아니라 "막히는 코드였다면 1,549ms였다"
- **측정하려다 다른 방어를 밟는 것 자체가 검증**이라는 것 — 422로 죽은 첫 실행이 SSRF의 첫 실서버 확인이었다
